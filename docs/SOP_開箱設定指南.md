# 娜娜開箱設定指南（SOP）

> 給第一次拿到娜娜的你。全程只需要一支手機＋約 15 分鐘。
> 流程：連上它的 WiFi → 申請一把免費金鑰＋建立機器人 → 填進設定頁 →
> **點一下連結完成 Telegram 綁定** → 完成。全程不用抄任何數字 ID。
> 本 SOP 已在出廠板實測通過（2026-07-21，SerialSoul v5.3）。

---

## 你需要準備

| 項目 | 說明 |
|------|------|
| 手機 | 用來設定與日常操作 |
| 家用 WiFi 名稱與密碼 | 2.4GHz（一般家用 WiFi 都支援）|
| Google 帳號 | 申請免費的 Gemini AI 金鑰 |
| Telegram App | 免費通訊軟體，跟娜娜傳訊息用 |

---

## 第 1 步　開機並連上它的熱點

1. 把娜娜插上電源（USB 5V）。
2. 等約 1 分鐘，**螢幕會顯示**：
   - 熱點名稱：`NANA-7A3E`（本板專屬）
   - 設定網址：`10.1.1.1`
   - 登入 PIN：6 位數字（每台不同，以螢幕顯示為準）
3. 手機打開「WiFi 設定」，連上 **`NANA-7A3E`**。螢幕若顯示「熱點密碼」就輸入它（每次都不同）；沒有顯示就免密碼。
4. **手機會顯示「這個網路沒有網際網路連線」的警告，這是正常的！**
   這個熱點本來就只是拿來設定用，本身不連外網。
   - iPhone：跳出「無網際網路連線」時，選**「仍要加入」／「保持連線」**（不要選「取消」，
     也不要因為看到警告就跑去 WiFi 設定把它關掉）。
   - Android：狀態列可能顯示「WiFi 沒有網際網路，點按以了解詳情」，
     或系統自動跳出「是否要連線？」，一律選**「是」／「維持連線」**。
5. 等 3～10 秒，**部分手機會自動跳出設定頁**（像連咖啡廳 WiFi 的登入畫面）；
   沒有自動跳出的話，手動開瀏覽器輸入 `http://10.1.1.1`（這是最保險的做法）。
6. 輸入螢幕上那組 6 位 PIN → 進入設定頁。

> 📌 熱點只在「它連不上網路」時出現。之後想改設定，見第 6 步的控制台。
> ⚠️ 如果手機自動把這個「無網路」的 WiFi 斷線（部分機型的省電/穩定網路功能），
> 到 WiFi 設定裡把 `NANA-7A3E` 重新點一次連上即可，不影響裝置本身。

---

## 第 2 步　申請 Gemini AI 金鑰（免費，3 分鐘）

這是娜娜的「大腦」，Google 提供免費額度，日常聊天綽綽有餘。

1. 手機瀏覽器開 **https://aistudio.google.com**，用 Google 帳號登入。
2. 點 **Get API key**（取得 API 金鑰）→ **Create API key**。
3. 複製那串 `AIza` 開頭的金鑰（先貼到記事本暫存）。

> ⚠️ 金鑰＝你的鑰匙，不要公開貼網路、不要給別人。

---

## 第 3 步　建立 Telegram 機器人（免費，3 分鐘，只要 token）

這是娜娜在 Telegram 上的「身分」。**這步只需要拿到一串 token，不用查任何 ID。**

1. 安裝並註冊 **Telegram**（App Store / Google Play）。
2. 在 Telegram 搜尋 **@BotFather**（有藍勾勾的官方帳號）→ 按 Start。
3. 傳 `/newbot`，照指示：
   - 取名字（例如 `NANA`）
   - 取帳號（必須 `bot` 結尾且未被使用，例如 `my_nana_home_bot`）
4. BotFather 會給你一串 **token**（長得像 `1234567890:ABCdef...`）——複製暫存。

> ⚠️ 每台娜娜必須用「自己的」bot token。兩台共用同一個 bot 會互搶訊息、兩台都收不到。

---

## 第 4 步　把三樣東西填進設定頁

回到 `http://10.1.1.1` 的設定頁（若斷線就重連熱點）：

| 欄位 | 填什麼 |
|------|--------|
| WiFi 名稱 / 密碼 | 你家的 WiFi |
| Gemini API Key | 第 2 步的 `AIza...` |
| Telegram Bot Token | 第 3 步的 `1234567890:ABC...` |

按 **「儲存並重啟裝置」** → 娜娜自動重開機（約 30 秒，連上你家 WiFi）。

---

## 第 5 步　點一下完成 Telegram 綁定（免查 ID）

裝置重開機、連上網路後（此時它還不知道要回覆給誰，這步就是要告訴它）：

1. 手機連**同一個家用 WiFi**（跟娜娜同一個網路），瀏覽器開它的控制台
   （網址見裝置螢幕，或參考第 6 步用 Telegram 問它也行——但這時還沒綁定，
   建議直接看螢幕上的 IP）。
2. 用 PIN 登入控制台 → 點下面分頁的 **「設定」**。
3. 找到 **🔗 Telegram 綁定** 卡片，按 **「點我加好友並綁定」**。
4. 手機自動開啟 Telegram、跳到你的機器人對話 → 按 **Start**。
5. 裝置幾秒內自動記住是你 → 回你一句「✅ 綁定成功！」→ **完成！**

之後傳 `/help` 看它全部本領。**不用查任何數字 ID，點一下、按 Start 就好。**

沒成功？最常見原因：
- WiFi 密碼打錯 → 它會重新開熱點，回第 1 步重填。
- 金鑰或 token 複製時多了空白 → 回設定頁重貼一次再存檔。
- 按「加好友並綁定」沒反應 → 通常是裝置剛開機還沒連上網，等 30 秒再試。
- 自己在 Telegram 搜尋機器人按 Start 不會綁定 → 一定要從控制台的按鈕進去（連結裡帶有一次性配對碼，別人光知道機器人帳號搶不走）。

## 第 6 步（日常）　網頁控制台

娜娜連上家用 WiFi 後，控制台搬到它的區網 IP：

1. 在 Telegram 傳 `/status`，回覆裡有它的 IP（例如 `192.168.0.79`）。
2. 手機連**同一個 WiFi**，瀏覽器開 `http://那個IP`。
3. 輸入同一組 PIN 登入（30 天內免重登）。
4. 四個分頁：**主控**（即時影像/對話/喇叭）、**排程**（自動任務）、**記憶＋技能**、**設定**。

> 控制台**不需要 Telegram 也能用**。不想用 Telegram 的話，WiFi 設定完就可以
> 直接在網頁上叫她做事、建定期任務、看她會什麼。Telegram 只是多一個「出門在外
> 也能收通知」的管道。

### 「有事才通知我」的定期任務（重點功能）

排程分頁 →「新增定期任務」→ 動作選 **👁️ 定時檢查，有事才通知我**：

1. 填「每幾分鐘」檢查一次。
2. 用**平常講話的方式**寫要盯什麼，例如「教室裡有沒有人趴著睡覺」
   「烤箱旁邊有沒有人」「看板上的產量數字是多少」。
3. （選填）先按主控分頁的「開始直播」，回到排程分頁就能在畫面上
   **用手指拉一個框**，她就只盯那一塊，其他地方一律忽略。
4. 勾「發生時也用喇叭唸出來」的話，除了通知還會出聲。

跟「📷 定時拍照回報」的差別：**監看只有真的發生才會吵你**，沒發生完全安靜。
拍照回報則是每次都報一次，適合單純想定期看看的情境。

她會自己把你那句白話轉成嚴謹的判讀指令並要求 JSON 格式回答，你不用會寫 prompt。

### 技能一覽（她到底會什麼）

記憶分頁下方的 **✨ 技能** 依「眼睛／排程／裝置／電腦／助理」分類，
點任一項展開就能看到**什麼講法會觸發它**。不確定該怎麼講的時候先來這裡看一眼，
照著那個意思講就會通——不用背指令。內建 24 個，上限 32 個，你可以自己再加 8 個。

其中四個是「幫你把話問清楚」用的，不是拿來執行動作的：

- **監控顧問**：你說「幫我盯著產線」這種沒講清楚的，她會反問「盯什麼？多久看一次？」
  而不是自己亂猜一個間隔就建下去。要求測量溫度、濕度這類數值時，
  她也會先確認畫面裡真的有那個儀表可以看——沒有就直說做不到。
- **長輩照護**：跌倒、久未活動這類情境的講法與合理間隔建議。
- **API 上報設定**：帶你把讀數送到自己系統的網址與欄位設定好。
- **故障排除**：沒收到通知、拍照失敗、連不上時，一步步問出是哪個環節。

## 讓她的聲音好聽一點（選填）

預設用 Google 免費語音，聽得懂但機械感重。想要自然的女生聲音：

1. 家裡電腦裝一下：`pip install edge-tts`
2. 執行 `python tools/tts_proxy.py`，它會印出一個網址。
3. 控制台 → 設定 → **好聽音色** → 把網址貼進去 → 存檔。

之後那台電腦開著時就是自然女聲；電腦關了會自動退回 Google 語音，不會啞掉（第一次會多等一下，之後 5 分鐘內直接走 Google 不再重試）。
音色可換：`zh-TW-HsiaoChenNeural`（台灣女聲，預設）、`zh-TW-HsiaoYuNeural`、
`zh-CN-XiaoxiaoNeural`（情感最豐富）。

## 拿來監看儀表板／工安時的裝機要點

這一節是實測出來的，照做可以少走很多冤枉路。

### 一、鏡頭方向要先調

裝置掛牆、倒吊、側放時拍出來的方向會不一樣。畫面顛倒會讓 AI 判讀變差。

```
/camera flip 0   正常
/camera flip 1   上下翻轉
/camera flip 2   左右鏡像
/camera flip 3   旋轉 180 度（裝置倒著裝就用這個）
```

設定立即生效並記住，先用「拍張照給我」確認方向對了再開始建任務。

### 二、**標籤要跟數字一樣看得清楚**（最容易被忽略的一點）

實測發現：如果數字很大但旁邊的**標籤**（產量／溫度／壓力…）太小，
鏡頭解析不出標籤，AI 就無法確認這個數字屬於哪個項目 ——
可能把溫度當成濕度回報。**貼錯標籤的讀數比沒有讀數更危險**，
因為數字是真的、看起來完全合理，操作員沒有任何線索能發現。

實測數據：標籤太小時，問「濕度是多少」有 15% 的機率會拿旁邊的溫度數字充數；
把標籤放大到與數字同一量級後，20 次測試全部正確拒答「畫面上沒有這個項目」。

裝機時的做法：
1. 用「拍張照給我」拍一張，自己看那張照片
2. **如果你自己在照片上看不清楚標籤，AI 也看不清楚**
3. 看不清楚就把鏡頭移近，或改用位置問（「最上面那個數字是多少」）

### 三、選對任務類型

| 你要的 | 用哪種 | 行為 |
|--------|--------|------|
| 每次都要有數值紀錄（產量、溫度） | 定時拍照回報 | 每輪都回報，不管有沒有異常 |
| 只有出事才通知（沒戴安全帽、有人跌倒） | 定時檢查有事才通知 | 符合才通知，不符合完全安靜 |

用講的就會通，例如「每 30 分鐘讀一次看板上的產量數字回報給我」、
「每 5 分鐘看有沒有人沒戴安全帽，有的話叫我」。

### 四、只盯畫面的某一區

整個畫面裡只有一小塊要看（某台機器、某個門口）時，
到控制台的排程分頁按「開始直播」，直接在畫面上**拖一個框**，
之後這個任務就只判讀那一塊。實測有效：全畫面有 3 個人沒戴安全帽時，
框選右半邊後 20 次都正確回答 2 個。

### 五、把讀數送進你自己的系統

不想只看 Telegram 通知、要把數值存進自己的資料庫或儀表板時：

```
/report set https://你的網域/api/readings
/report token 你的token          （選填，會帶 Authorization: Bearer）
/report test                      送一筆測試資料，確認你那邊接得到
/report                           看目前設定與完整欄位說明
/report off                       關閉上報
```

**設定當下就會驗證網址**——少了 `https://`、只給網域沒有路徑、網址裡有空格，
都會當場擋下並告訴你哪裡不對，不會讓你以為設好了、等到任務跑三輪失敗才發現。

送出的 JSON 欄位是**固定的**，方便你寫接收程式：

| 欄位 | 型別 | 說明 |
|------|------|------|
| `device` | string | 裝置名稱（與熱點同名）。多台裝置寫進同一個資料庫時靠這個分辨 |
| `task_id` | int | 哪一個定期任務 |
| `task_type` | string | `camera`（每輪都報）／`watch`（條件式）／`test` |
| `ts` | int | Unix 秒（裝置已對時） |
| `prompt` | string | 當初設定要看什麼 |
| `value` | string | 抽出的數值。**讀不到是空字串，不會塞 0** |
| `text` | string | 完整回覆原文 |
| `hit` | bool | `watch` 專用：條件成立與否。`camera` 恆為 true |
| `ok` | bool | 這一輪判讀本身成功與否 |

兩個設計上的取捨，你寫接收端時要知道：

- **`watch` 沒觸發也會上報，`hit=false`。** 對監控來說「這一輪檢查過了、沒事」
  本身就是紀錄；只存異常的話，資料庫裡分不出「一切正常」與「根本沒在跑」。
- **`value` 讀不到就是空字串。** 硬塞 0 會變成假資料，之後畫圖會看到不存在的低點。

上報連續失敗 3 次會主動通知你——**資料默默掉了比不上報更糟**。

### 六、監控壞掉時它會主動告訴你

相機被遮住、鏡頭髒了、網路不穩、AI 額度用盡 —— 這些都會讓監控停止運作。
連續 3 輪都失敗時會主動發一則通知：

> ⚠️ 任務#N 連續 3 輪失敗，目前沒有在正常監控。
> 常見原因：相機被遮住或鏡頭髒了、網路不穩、AI 額度用盡。

排除問題後會自動恢復，並再發一則「已恢復正常運作」。
**不會默默停掉讓你以為一切正常。**

在告警之前它已經自己試過了。每一輪失敗會這樣處理：

```
判讀失敗 → 還有重試額度？
            ├─ 有 → 調高判讀溫度，70 秒後再試（單輪最多 5 次）
            └─ 沒有 → 放棄這一輪，等下一個正常間隔
                       連續 3 輪都失敗 → 通知你
```

兩個細節值得知道：

- **重試會換參數，不是原封不動重跑。** 同一張圖 + 同一句提示詞 + 同一個溫度，
  重跑十次通常還是同一個結果，只是白花 AI 額度。所以每次重試會把判讀溫度
  往上調 0.4 → 0.6 → 0.8（上限 0.9），成功後歸位。
- **重試間隔是 70 秒不是隨便設的。** AI 呼叫有每 60 秒 5 次的上限，
  等過完整個速率視窗再試才有意義，太快重試只會再撞一次額度不足。

### 判讀太保守或太浮誇時：調溫度

| 指令 | 效果 |
|------|------|
| `/ai temp` | 看目前用的值 |
| `/ai temp auto` | 交給系統自己調（預設） |
| `/ai temp 0.6` | 固定成指定值，不再自動調整 |

低（0.0~0.3）＝答案穩定，同一張圖問兩次結果幾乎一樣，**讀儀表數字建議用這個**。
高（0.7~1.0）＝比較願意猜，適合描述場景，但數字容易飄。

## 換 WiFi／搬家

兩種都可以，設定與記憶都會完整保留：

- **主動進設定模式**（推薦，換 WiFi 前先做）
  控制台 → 設定 → **📶 換 WiFi／重新設定**，或在 Telegram 傳 `/setup`。
  裝置重開機變回熱點，照第 1 步重填即可。
  > 按錯了？拔電重插就回正常運作，什麼都不會掉。

- **什麼都不做**
