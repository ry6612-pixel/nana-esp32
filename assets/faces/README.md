# 娜娜的表情插畫（LCD 點陣圖）

螢幕上顯示的是**預先畫好的插畫**，裝置只負責把像素貼上去，不是現場畫圖形。

這件事踩過一次坑值得寫下來：早期版本用即時向量繪圖（程式碼畫圓／橢圓／弧線）
組出一張臉，怎麼調都停在「簡單圖形」等級，到不了插畫質感；後來改成貼圖之後，
又試過在插畫臉上疊向量弧線做笑臉／眼皮，同樣很突兀（線稿風格對不起來）。
結論：**臉上不要再畫任何向量圖形，要換表情就換整張圖。**

## 現有四張

| 檔案 | 表情 | AI 用的標籤 | 出現比例 |
|------|------|------------|---------|
| `neutral.rgb565` | 平常、嘴微張 | `[FACE:neutral]` | 約 30% |
| `smile.rgb565` | 抿嘴微笑 | `[FACE:smile]` | 約 30% |
| `happy.rgb565` | 大笑、眼睛瞇起來 | `[FACE:happy]` | 約 30% |
| `love.rgb565` | 雙手比愛心 | `[FACE:love]` | 約 10%（刻意少見） |

比例由兩層決定：AI 回覆時自己選標籤（system prompt 有寫目標比例），
沒帶標籤時韌體用 `weighted_default_expression()` 依 30/30/30/10 隨機挑。

講話動畫也是換圖做的：`FaceImage::talk_partner()` 在「閉嘴」跟「開嘴」兩張
真圖之間輪替。比愛心那張沒有配對圖（換圖會讓雙手閃爍），所以講話時不動。

## 換成自己的角色

1. 準備四張圖，**同一個角色、同一個構圖、頭的位置要一致** —— 這點很重要，
   四張圖是共用同一個裁切框做出來的，位置不一致的話換表情時頭會在螢幕上跳。
2. 裁成正方形放進 `src/`，檔名要正好是 `neutral.jpg` / `smile.jpg` /
   `happy.jpg` / `love.jpg`。
3. 轉檔：

```bash
pip install pillow
python tools/build_face_assets.py
```

預設輸出 216×216。改尺寸要同步改 `board_hw.rs` 的 `FACE_W` / `FACE_H`
（`python tools/build_face_assets.py --size 200`）。

轉出的 `.rgb565` 是每像素 2 bytes、大端序、無檔頭的裸資料，
`board_hw.rs` 用 `include_bytes!` 內嵌，`blit_face_bitmap()` 貼到螢幕上。
單檔 216×216 約 93 KB，四張約 373 KB，app 分割區有 4 MB，空間充裕。

`tools/png_to_rgb565.py` 是單張轉檔的通用版本，臨時測一張圖時比較方便。

## 螢幕顏色不對時

先查 `board_hw.rs` 裡 mipidsi `Builder` 的 `.color_order()` 與
`.invert_colors()` —— 不同批次的 ST7789 面板這兩項設定不一樣，
設錯的徵兆是「白色變黑」「紅藍互換」。這是硬體設定問題，
不是圖片資料壞掉，不用重轉檔。

## 版權提醒

不要把受版權保護的既有角色當成最終要嵌進韌體的素材，請用原創角色或
生圖工具產出的原創插畫。私人送禮風險較低，但避免直接複製特定角色的
識別特徵（髮型髮飾、瞳色組合等）比較保險。
